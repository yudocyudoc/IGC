# ARENA EV-03 — Precompromiso: ingestión de un log operacional REAL público sin inferir tiempos físicos

Fecha: 2026-11-01 (México). **PRIMER COMMIT de EV-03, ANTES de código o ejecución**. Base exacta: head EV-02 PR #132 `e0eec08d31f75a010fbe21d3d7aa8d8521b2bd08`. Rama y PR Draft apilados sin merge, sin modificar CAF-01..16, MC-01, EV-01/02, D/B/M o ATMS.

## Problema
Hasta EV-02 solo hemos probado exportaciones fabricadas a partir de nuestro DES. No tenemos CSV real autorizado de una cafetería o CRM del usuario. EV-03 ejecuta un ensayo con **registro real histórico publicado por un tercero** para verificar la ingeniería de ingestión, no la identificabilidad de la cafetería. En paralelo entrega un contrato de intake real preparado para operar cuando exista una exportación autorizada, pero no inventa proveedor, datos, verificaciones de relojes ni consentimiento.

## Fuente externa predeclarada
**BPI Challenge 2012** (van Dongen, 2012), registro de solicitudes de crédito de una institución financiera neerlandesa, DOI original `10.4121/uuid:3926db30-f712-4394-aebc-75976070e91f`, XES comprimido publicado por 4TU.ResearchData. URL de versión exacta identificada en documentación del dataset:
`https://data.4tu.nl/file/533f66a4-8911-4ac7-8612-1235d65d1f37/3276db7f-8bee-4f2b-88ee-92dbffb5a893`.
Los registros distinguen eventos de aplicación (A_), oferta (O_), trabajo (W_) y atributos de ciclo de vida. No asumir que un evento `START` corresponde al inicio físico de trabajo ni que `COMPLETE` refleja tiempo efectivo de recurso. No publicar filas, case IDs, recursos, cantidades, nombres ni archivo raw de este tercero. Usar descarga HTTPS de fuente oficial durante CI, **sin fallback a mirrors**. Calcular SHA256 de bytes y registrarlo; al no disponer todavía de digest oficial predeclarado, el ensayo de datos externos será **`SOURCE_VERSION_PINNED_BYTES_NOT_PRECOMMITTED`** y NO podrá reivindicar reproducibilidad byte a byte hasta congelar/verificar un hash externo de referencia. La primera ejecución puede fallar por disponibilidad de 4TU; tal fallo será `NOT_RUN_EXTERNAL_DATA_UNAVAILABLE`, nunca evidencia empírica.

## API nueva y separación de responsabilidades
- `scripts/arena_public_eventlog_intake.py`: lector de flujo XES y XES.gz externo, exclusivamente estándar Python, con controles de tamaño/número de eventos y trazas, rechazo de XML DTD/entidades externas, validación de timestamps ISO aware, reprocesamiento tolerante a eventos incompletos (cuarentena agregada, SIN copiar payload), agregados de calidad por actividad/lifecycle/casos. **No importa CAF, PM4Py, ATMS ni simuladores.** No confiar en etiquetas de proveedor para atribuir duración física, colas ni recursos.
- `experiments/cafeteria/pc02/arena_ev03_public_log_probe.py`: orquestador de auditoría que acepta archivo XES.gz predescargado de ruta local o fixture XES fabricado para pruebas unitarias. La ruta pública y el origen son parámetros explícitos, no acceso implícito a secretos. Descarga externa en CI solo, fuera del código del parser; no reenviar datos a otros servicios.
- Semántica de caso: `concept:name` de traza se trata como identificador opaco (nunca exportado), eventos con `concept:name` actividad, `time:timestamp` aware y `lifecycle:transition` si existe. Sin inventar `event_id` natural en XES: ordinal de archivo es identificador técnico solo dentro del proceso de lectura, NO exportado en resultado. No asumir que A_, O_, W_ conforman etapas de servicio secuenciales.
- Métricas de validación: número de trazas/eventos, evento fechado/no fechado, evento sin actividad, timestamps sin desplazamiento, orden temporal dentro de caso, número de actividades distintas, completitud de lifecycle, número de recursos reportados por evento **sin exportar valores**. Ciclo computable solo como `elapsed_first_to_last_observed_event` si existen dos timestamps y no hay contradicción cronológica; NO tiempo físico de servicio, NO duración total del proceso fuera de ventana, NO espera real. Promedios solo descriptivos cuando proceda, no porcentaje de diagnósticos.
- Ninguna reclamación de procesos ocultos, cuello de botella, capacidad, recursos finitos, causalidad ni topología. Estado de salida `PUBLIC_OPERATIONAL_EVENTLOG_SCHEMA_AUDITED_NOT_PHYSICAL_VALIDATED` cuando se ingieren eventos reales; o `SYNTHETIC_PARSER_TEST_ONLY` en pruebas fabricadas. Gate de validación empresarial sigue bloqueado.

## Aceptación y seguridad
1. Precommitar protocolo; código posterior. CI unitario ejecuta al menos 10 pruebas de XML/XES y compresión, DTD rechazo, timestamps sin zona, evento faltante, out-of-order, colisión de actividad, size caps, no fuga de IDs, no numerología de tiempo físico; compara agregados esperados contra fixtures.
2. CI externo descargar archivo desde 4TU con `curl --fail --location --retry 2`, timeout y tamaño máximo 64 MiB comprimido, con checksum registrado. No almacenar el raw en artifact; solo `00_PLAN.json`, `01_RESULTADOS.json`, `02_INFORME.md`, `03_MANIFIESTO.json`. Confirmar que realmente se abrió un XES.gz y que sus trazas contienen eventos. Evitar umbrales post hoc de «rendimiento».
3. No fijar número real de trazas/eventos como gate de éxito si la fuente pudiera tener actualización de bytes; registrar conteos reales, anomalías y tamaño, sin inferir exactitud física. Las pruebas sí pueden comprobar que se encontraron casos y actividades sin exponer identificadores. No usar el dataset como prueba de cobertura POS/KDS ni de una cafetería.
4. Contrato de preparación para ingestión de empresa (sin usarlo aún): procedencia documental del proveedor, autorización/bases de uso y retención, descripción de cada hito, enlace legítimo de entidad, timezone/resolución/precisión/reloj, datos personales y campos prohibidos, ausencias y reintentos, dependencia entre trazas/objetos, estado de sincronización independiente. Sin documento no ejecutar inferencia física.
5. El repositorio no debe contener credenciales, nombres reales o registro fuente; CI usa GitHub Actions con permisos read. Verificar hashes SHA256 de artefactos y distinguir head SHA del checkout merge SHA.
6. **Gate:** `BLOCKED_REAL_BUSINESS_INSTRUMENTATION_AND_PHYSICAL_SEMANTICS_NOT_VALIDATED`, aunque el log de 4TU sea real. Mantener PR Draft sin merge y registrar fallos sin maquillarlos.

## Contraste epistémico
El log de crédito es **externo y operacional real** según su fuente histórica, pero los timestamps siguen siendo registros de sistema. El hecho de superar el parser y reconstruir secuencias no identifica duración de trabajo físico ni etapa latente; EV-03 no intenta repetir errores de CAF sobreidentificando mecanismos desde señales insuficientes.
